# Agent 선택 및 사용 후 평가

## 선택

Orchestrator는 각 Step 시작 시 요구사항과 Unknowns를 기준으로 [역할 목록](../agents/README.md)에서 필요한 역할만 선택하고 사유를 기록한다.
사용하지 않은 역할은 이번 범위에서 제외한 것으로 기록한다. 한 검토에서 불필요했다는 이유로 공통 역할을 삭제하지 않는다.
역할 파일은 검토 지침이며 별도 실행 설정이 아니다. 사용 가능한 실행 방식에 맞게 적용하되 단일 에이전트의 역할별 검토와 별도 에이전트의 독립 검토를 구분해 기록한다.

## 매 사용 후 평가

전문 역할, Orchestrator, Reviewer, Historian/Reporter 모두 작업 단위가 끝날 때 [평가 템플릿](../templates/AGENT-EVALUATION-TEMPLATE.md)을 작성한다.
같은 Step의 평가는 하나의 파일에 역할별 행으로 묶을 수 있다. 전문 역할은 결과 반환 시, 조정·검토·보고 역할은 해당 작업 종료 시 평가한다. 평가 문서 작성 자체를 새 역할 사용으로 재귀 평가하지 않는다.

- 위치: 해당 Assessment의 `evaluations/`. 하네스 자체 개선의 역할 검토는 `history/`에 둔다.
- 기록: 역할 파일, 작업 범위, 입력, 산출물, 수행/평가 주체, 실행 방식, 아래 평가와 후속 행동.
- 평가 기준: 요구사항 충족, 근거의 정확성, 실행·운영 가능성, 다른 역할과의 중복, 누락 영역.
- 각 기준은 `충족 / 보완 필요 / 미평가 / 해당 없음`으로 표시하고 증거·사유를 남긴다. 아직 사용하지 않은 역할의 성능을 추정하지 않는다.
- 실행 시간·비용이 계측된 경우에만 기록한다. 평가자와 수행자가 같으면 자기 검토로 명시한다.
- Reviewer는 전문 결과의 문제를 검토하고 Orchestrator는 평가 누락, 역할 간 공백, 후속 조치를 확인한다. 같은 수행자가 둘을 맡으면 독립 검토라고 표현하지 않는다.

## 평가에 따른 변경

| 판단 | 행동 |
|---|---|
| 유지 | 다음 관련 작업에서도 사용 |
| 이번 범위 제외 | 제외 근거만 남기고 공통 역할 유지 |
| 보완 | 입력·산출물·체크리스트 또는 책임 경계 개선 |
| 추가 / 분리 | 기존 역할로 해결되지 않는 영역과 산출물을 정의하고 역할 추가 |
| 통합 / 비활성 | 반복된 중복·무효용 근거, 책임 인계, 기존 참조 보존 후 적용 |

필요한 역할 추가·보완은 문서 변경 범위에서 AUTO로 진행하고 역할 목록, 관련 템플릿, 이력을 함께 갱신한다.
비활성 역할은 목록에 상태·사유·대체 역할을 남기고 파일을 보존한다. 기존 검토와 승인 증거를 삭제하지 않는다.
역할 변경이 아키텍처 선택이나 승인된 범위를 바꾸면 별도의 Decision으로 다룬다.
평가에서 발견한 필수 누락은 해당 Gate 완료 전에 보완한다. 일반적인 개선은 담당 역할과 재검토 시점을 기록해 후속 작업으로 남길 수 있다.
