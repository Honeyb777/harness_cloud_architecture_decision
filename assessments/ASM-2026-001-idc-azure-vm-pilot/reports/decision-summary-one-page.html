Azure VM 파일 배포 전환 — 의사결정 요약

IDC Java/Kotlin Tomcat 및 Vue 정적 파일 · 2026-09-07 · 검토 단계: Discovery

무엇을 결정하는가: GitHub Actions로 만든 파일을 Azure VM 두 대에 안전하게 순차 배포하는 운영 방식을 정한다. 이 문서는 선택을 위한 보고서이며, Azure/GitHub 설정·권한 부여·실제 배포·Pilot 검증은 아직 수행하지 않았다.

권장 배포 흐름 아직 선택 전

소스 변경각 서비스 저장소
→
CI 빌드·검사고정 빌드 이미지 + Cache
→
배포본 보관release ID·digest
→
배포 대기열공유 VM pair 잠금
→
VM 1 → VM 2drain·교체·준비 확인

이미 정리된 방향 사용자 방향 반영

  • Tomcat은 별도 포트 JVM 없이 같은 포트에서 교체한다.
  • Nginx readiness marker로 신규 요청을 제외한 뒤 drain, 교체, readiness/warm-up 확인 순서로 진행한다.
  • Actions Cache와 Key Vault를 사용한다. 기존 GitLab/Jenkins/Nexus/Ansible은 새 운영 구성요소가 아니다.

VM 순차 전환 그림

VM 2 정상용량 확인
→
VM 1 drain신규 요청 제외
→

두 VM을 동시에 배포하지 않는다. VM 1의 준비 확인이 실패하면 VM 2에는 진행하지 않는다.

선택 후 수치화할 운영 기준 미정

  • 보관 release 수, 롤백 보장 기간, 이전 asset 지원 기간
  • drain 제한 시간, 긴 요청/WebSocket 처리, warm-up 관찰 시간
  • 한 VM 장애 중 허용 용량, HOLD·롤백 기준, RTO/RPO
  • 사내 Maven/npm 공급원 이관·폐기와 비용 측정 기준
권장 결정 순서: 1) 중앙 배포 대기열 여부 → 2) VM 전달 및 네트워크 경로 → 3) Blob/Artifacts와 보관 기간 → 4) 빌드 이미지와 정적 asset 방식 → 5) Pilot으로 drain·rollback·비용을 검증.

상세 설명은 이 파일과 함께 제공되는 “상세 의사결정 보고서”에 포함한다. GitHub·Azure 권한 모델은 별도 보안·Identity 검토 범위다.
