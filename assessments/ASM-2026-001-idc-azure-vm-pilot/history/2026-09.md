# 2026-09

## 2026-09-07 — 파일럿 요구사항 접수 및 공식 조사

- IDC 현행 GitLab/Jenkins/Nexus/Ansible·L4 수동 제외/재투입과 Azure 목표를 접수했다.
- GitHub Enterprise Cloud, 서비스별 별도 Tomcat/JVM을 후속 답변으로 확인했다. 네트워크 제약은 미정이다.
- OIDC workload identity와 승인자 권한 분리, hosted runner 대안, VM Agent 배포와 Blob MI 접근을 검토했다.
- probe와 connection drain 차이, pair 공통 잠금/영속 상태, Tomcat warm-up·세션, Vue 양 서버 asset 선배치를 권장안으로 기록했다.
- 결정: [사용자 지정 범위](../decisions/DEC-2026-001-pilot-scope.md)는 DECIDED. [배포 신뢰 경계](../decisions/DEC-2026-002-deployment-trust-boundary.md)는 PROPOSED.
- 검증: 공식 출처 확인 및 로컬 문서 검사만 수행. Azure/GitHub 실제 설정·배포 시험·커밋은 수행하지 않았다.
- Ref: [역할 평가](../evaluations/2026-09-07-discovery.md), [검증 계획](../evidence/pilot-validation-plan.md).

## 2026-09-07 — Hosted 전환 후속 정리

ASM-2026-001에 기존 GitLab/Jenkins/Nexus/Ansible 제외, Actions Cache·Key Vault 도입, 추가 모듈의 빌드 용도, 단일 포트 JVM 및 JWT/DB·API 위험 수용을 DEC-2026-003으로 반영했다. 명령 push·파일 pull과 자율 pull, 공개/사설 데이터 접근, 선택적 GHCR, 정적 release 전환을 비교했다. 이전 조사에서의 Nexus/Ansible 재사용·별도 포트 JVM 후보는 현재 범위에서 제외한다. 검증 항목과 역할 자기 평가를 추가했으며 실제 적용·커밋은 수행하지 않았다.

## 2026-09-07 — 배포 절차 초안 기록

사용자 요청에 따라 GitHub Actions의 build·승인·OIDC·Blob release, pair 잠금, Application Gateway 기반 VM별 drain, Run Command와 VM Managed Identity, 단일 포트 Tomcat 재기동, Vue release/current 포인터 전환, 검증·복구·기록 순서를 배포 초안으로 정리했다. 네트워크 방식, 실제 권한, drain 기준, 보존 정책은 미확정이며 Azure/GitHub 적용이나 배포 시험은 수행하지 않았다. [배포 절차 초안](../reports/deployment-draft.md)을 참조한다.

## 2026-09-07 — Microsoft 협의 질문 초안

Application Gateway의 probe·connection draining과 pipeline의 실행 순서를 쉽게 설명하고, Microsoft 영업·기술 담당자의 제품 소개에서 권장 아키텍처·지원 범위·PoC 범위를 확인하는 아젠다를 작성했다. GitHub 사람 권한, Environment 승인, OIDC, Azure RBAC 및 VM Managed Identity를 역할별로 풀어 소개받도록 구성했다. [협의 질문 목록](../reports/ms-meeting-question-list.md)을 참조한다. 실제 제품 구성이나 검증은 수행하지 않았다.

## 2026-09-08 — CD 조정·트래픽 전환·identity 비교 보강

GitHub Actions 단독의 중앙 deployment repository/pair lock과 Azure Pipelines Environment exclusive lock을 비용·운영 책임과 함께 비교하도록 미팅 아젠다를 보강했다. Application Gateway의 명시적 backend 제외와 Nginx readiness probe, GitHub OIDC·Azure workload identity·VM Managed Identity의 역할, Blob·Key Vault 사설망 선택의 이유를 분리해 질문으로 정리했다. Azure Pipelines 공개 가격·무료 사용량은 조사 시점 정보이며 계약별 실제 비용은 Microsoft 견적 확인이 필요하다. 실제 제품 구성이나 검증은 수행하지 않았다.

## 2026-09-08 — 내부 결정과 Microsoft 확인 항목 분리

파일럿 범위·성공 기준·release manifest는 내부 결정으로 분리하고, Microsoft에게는 GitHub Enterprise Cloud와 Azure 권한 best practice, private GHCR/ACR, shared VM pair의 CD 조정, Application Gateway/Nginx/connection draining, passwordless identity와 Storage network 경계를 확인하도록 아젠다를 재구성했다. identity가 권한을, private endpoint가 네트워크 경로를 각각 해결한다는 점을 명시했다. 실제 제품 구성이나 검증은 수행하지 않았다.

## 2026-09-08 — 질문별 비교 기준 분리

Microsoft 미팅 질문을 ID별 표로 바꾸고, 각 질문에 목적·기대 답변 또는 비교 기준·답변 메모·내부 결정을 붙였다. GitHub/Azure 권한, CI registry, CD concurrency·push/pull, Application Gateway connection draining, Storage network를 서로 독립적으로 기록·비교할 수 있게 했다. 실제 제품 구성이나 검증은 수행하지 않았다.

## 2026-09-08 — GitHub 권한·production 보호 모델 초안

GitHub Enterprise Cloud의 Enterprise부터 workflow job까지 권한 계층, Environment와 branch의 차이, repository 기본 역할, Organization·Team·custom 역할, production Environment와 workflow 보호 설정을 리포트로 정리했다. GitHub 승인·job permission과 Azure OIDC/RBAC·VM Managed Identity를 분리해 기록했으며 실제 권한 설정은 수행하지 않았다.

## 2026-09-08 — Azure 관리·identity·권한 모델 초안

GitHub 권한 리포트와 분리해 Azure의 비용·리소스·Entra identity 계층, 환경별 workload/VM identity, Azure RBAC, Blob lifecycle, ACR repository 권한, private endpoint와 identity의 역할 차이를 리포트로 정리했다. 실제 Azure resource·identity·role assignment·network 설정은 수행하지 않았다.

## 2026-09-08 — GitHub-Azure OIDC 연결 모델 초안

GitHub Environment 보호·job OIDC permission과 Azure workload identity의 federated credential·RBAC·VM Managed Identity를 연결하는 설정·사용·거부 시험·감사 순서를 별도 리포트로 작성했다. 실제 OIDC claim·federated credential·role assignment는 미확정이며 Azure/GitHub 설정은 수행하지 않았다.

## 2026-09-07 — GitHub 권한과 Azure Identity 선택 분리

STEP-01 Discovery에서 GitHub repository의 사람 권한, workflow job 권한, Azure workload identity/RBAC를 별도 층으로 분류했다. 중앙 deployment repository와 환경별 UAMI 또는 Entra app 선택은 사용자 결정 후보로 남겼으며, 실제 GitHub·Entra·Azure 설정 변경은 수행하지 않았다. [선택안](../designs/github-access-and-identity-governance-options.md)을 참조한다.

같은 선택안에 GitHub 사람·job 권한과 Azure 사람·workload identity·RBAC를 좌우로 분리한 권한 배치표를 추가했다. SSO는 로그인 연계일 뿐 양쪽 권한의 자동 동기화가 아니라는 기준을 명시했다.

## 2026-09-07 — CI/CD 단계와 build image 선택 정리

repository workflow, GitHub-hosted runner image, 선택적인 job container build image, GHCR·ACR registry를 분리해 CI/CD 단계를 정리했다. 파일럿 기본안은 hosted runner에서 도구를 설치하는 방식이며, ACR은 VM runtime container 또는 Azure private registry 요구가 확인될 때만 재검토한다. [CI/CD 선택안](../designs/ci-cd-stages-and-build-image-options.md)을 참조한다.

사용자 요청에 따라 JDK·Node·추가 CLI를 고정한 build container image를 GHCR 또는 ACR에서 관리하는 요구사항을 추가했다. GitHub Enterprise Cloud의 Packages 50GB allowance와 GHCR Container registry의 현행 별도 무료 정책을 구분했고, registry 선택은 [DEC-2026-004](../decisions/DEC-2026-004-build-image-registry.md) USER_DECISION 후보로 기록했다. 실제 image·registry·권한 생성은 미수행이다.

## 2026-09-07 — Build cache와 배포 release 생명주기 분리

Actions Cache, GitHub Packages, GHCR/ACR build image, Actions Artifacts, Azure Blob의 책임과 lifecycle을 분리했다. GitHub Packages는 사내 dependency의 영속 registry로, Actions Cache는 재생성 가능한 dependency cache로 기록했다. Blob을 canonical VM release store로 하고 Artifacts는 증적으로 사용하는 권장안을 [DEC-2026-005](../decisions/DEC-2026-005-release-canonical-store.md)에 남겼다. N개 보존·rollback pin·frontend asset 보호·soft delete/versioning·cleanup 권한은 미결정이다.

Artifacts가 job 간 build 결과를 전달할 수는 있지만 private build image의 최초 pull이나 JDK·Node·CLI 제공을 대체하지 않는다는 경계를 추가했다. GHCR을 선택할 경우 private package, package read 최소 권한, `GITHUB_TOKEN` 기반 사전 pull, digest 고정으로 운영하는 정책 초안을 기록했다. registry 선택 및 실제 설정은 미결정·미수행이다.

GitHub-hosted runner가 할당된 뒤 private image pull, package/cache 처리, artifact·Blob 전송이 실행되므로 모두 runner 시간에 포함된다는 비용 영향을 추가했다. standard runner와 larger runner custom image의 과금 차이, 단계별 시간 측정 계획을 기록했으며 실제 비용·성능은 미측정이다.

## 2026-09-07 — CD 순차 제어와 Azure OIDC 준비

GitHub concurrency의 repository 범위와 `queue: max` 제한, 중앙 deployment repository와 영속 pair lock의 조합을 정리했다. pending/Environment wait와 runner step 내부 대기의 시간·과금 차이를 검증 항목으로 추가했다. Azure CD 인증은 Key Vault나 Azure client secret이 아니라 GitHub OIDC·Entra federated credential·환경별 최소 RBAC로 준비하며, Key Vault는 VM/Gateway 런타임 secret 용도로 분리했다. 실제 설정·권한 부여·시험은 미수행이다.

중앙 deployment repository에 Environment별 Azure identity 식별자 secrets를 한 번만 두고, source repository는 CI·release publish, 중앙 repository는 자동 CD와 고정 release ID의 수동 재배포를 담당하는 흐름을 명시했다. source repository별 Azure CD secret 복사는 기본안에서 제외한다.

## 2026-09-07 — CD 운영 모델 선택 분리

공유 VM 쌍의 CD를 중앙 deployment repository가 자동 queue로 조정하는 모델과, 각 service repository에서 지정 운영자가 수동으로 순서를 조정하는 모델로 분리했다. 두 모델 모두 공통 pair lock·HOLD·OIDC workload identity가 필요하며, GitHub concurrency만으로 교차 repository 배포를 막을 수 없음을 명시했다. [DEC-2026-006](../decisions/DEC-2026-006-cd-operation-model.md)은 USER_DECISION 후보이며 실제 적용은 미수행이다.

## 2026-09-07 — VM 배포 전송 모델 선택 분리

GitHub Actions runner가 SSH 등으로 파일·명령을 직접 push하는 모델과, GitHub OIDC로 Azure Managed Run Command만 push하고 VM Managed Identity가 Blob release를 pull하는 모델을 비교했다. GitHub OIDC가 SSH 인증을 대체하지 않는다는 점과 private runner network·SSH credential 또는 Azure Agent/MI의 조건을 분리했다. [DEC-2026-007](../decisions/DEC-2026-007-server-deployment-transport.md)은 USER_DECISION 후보이며 실제 설정·시험은 미수행이다.

## 2026-09-07 — Tomcat rollout 모델 비교

Application Gateway probe marker로 신규 요청을 제외한 뒤 같은 port의 Tomcat을 교체하는 방식과, 별도 port에 새 JVM을 병행해 traffic을 전환하는 방식을 비교했다. DEC-2026-003의 기존 사용자 결정에 따라 same-port drain 교체를 현재 선택으로 유지하고, 별도 port 방식은 재결정·capacity·Gateway·공존 검증 조건이 갖춰질 때만 재검토한다. 실제 drain·warm-up·Gateway 설정 시험은 미수행이다.

사용자 지시에 따라 별도 port JVM 병행 비교를 현재 검토 대상에서 제거하고 same-port drain·교체 절차만 남겼다. Frontend는 단일 slot 전환 시 이전 자산 요청의 사용자 영향을 수용하는 모델과 hash/version 자산 두 버전을 함께 제공하는 모델을 [DEC-2026-008](../decisions/DEC-2026-008-frontend-static-asset-rollout.md)으로 분리했다. 확인되지 않은 frontend 이슈는 사용자 확인 전 설계에 추가하지 않는다.

Frontend B안에 r101→r102 directory·Nginx path·두 VM 준비/HTML 전환·rollback/cleanup 예시를 추가했다. 이 예시는 이전 정적 자산 URL을 보존하는 범위만 설명하며, 확인되지 않은 frontend 이슈를 추가하지 않았다.
## 2026-09-07 — 의사결정 보고서 HTML 추가

GitHub·Azure 권한 과제를 제외한 미정 정책을 한 장짜리 의사결정 요약과 상세 HTML 보고서로 분리했다. 두 보고서는 현재 상태를 `STEP-01 / DISCOVERY / IN_PROGRESS`로 표시하고, 권장안·사용자 선택 필요 항목·실제 적용 미수행을 구분한다.

- [의사결정 1장 요약](../reports/decision-summary-one-page.html)
- [상세 의사결정 보고서](../reports/decision-detail.html)

상세 보고서에는 DEC-2026-004~008의 선택지와 권장안, release lifecycle·가용성·패키지/비용의 수치화 과제, 환경 확인 항목, Pilot 검증 전제조건을 연결했다. 새 Azure/GitHub 구성이나 권한 변경, 배포, 검증은 수행하지 않았다.
## 2026-09-07 — 독립 공유용 HTML 보고서 보완

1장 요약과 상세 HTML 보고서를 외부 공유 가능한 독립 산출물로 다시 구성했다. 내부 Decision ID와 저장소 상대 링크를 본문에서 제거하고, 배포 전체 흐름, VM 순차 전환, build/release 역할 분리, VM 전달 방식, frontend asset 전환 흐름을 그림으로 추가했다. 선택지·권장안·근거·미확인 사항·Pilot 미수행 상태는 보고서 본문에 직접 포함했으며 공개 공식 문서 링크만 참고로 남겼다.
## 2026-09-07 — Azure Pipelines CD 조정기 후보 추가

GitHub Actions CI를 유지하면서 Azure Pipelines를 CD에만 사용하는 세 번째 운영 모델을 추가했다. Azure DevOps Environment approval/exclusive lock은 배포 대기열과 승인에 사용할 수 있으나, Application Gateway connection draining, Nginx readiness, VM 순차 전환, HOLD/rollback을 대체하지 않음을 명시했다. 실제 Azure DevOps 조직·billing·Pipeline·service connection·배포 시험은 수행하지 않았다.
